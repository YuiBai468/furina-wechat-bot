# 芙宁娜 · 微信 AI 伴侣

> 一个跑在自己电脑上的微信 AI 聊天机器人。它不是客服，是一个有作息、有脾气、会自己刷 B 站、会主动找你的「人」。

基于 **DeepSeek** 的 API + [wechatauto-replica](https://github.com/fanyuantaier/wechatauto-replica) 的微信自动化，不经过任何第三方服务器 —— 消息直接从你本地的微信客户端读，回复直接发出去。

```
       你 ⇄ 微信客户端 ⇄ wechatauto（本地读库 + UI 自动化）⇄ 本程序 ⇄ DeepSeek API
```

---

## 它是什么

不是一个「帮你干活的助手」，是一个**扮演特定角色的聊天对象**。开箱自带的人设是《原神》的**芙宁娜**，但你完全可以把 `persona/furina.md` 换成任何你想扮演的角色。

它的核心不是「回答问题」，是**像一个真人那样发微信**：

- **消息是气泡的**：一个念头一条，不会一口气发一大段
- **有作息**：会早安、催饭、说晚安，凌晨会困
- **会主动找你**：不是等你说话
- **有情绪**：会吃醋、会嘴硬、会不好意思
- **会自己刷 B 站**：看到有意思的视频会转给你，还会先自己看完再评论
- **你发链接它也会看**：粘一个 B 站视频过去，它下载、看画面、听语音，然后跟你聊

## 特性

### 像人一样发消息

| | |
|---|---|
| 气泡拆分 | 一条回复按换行拆成多条消息，模拟一口气说几句话 |
| 首条延迟 | 1~5 秒，不会秒回 |
| 打字节奏 | 气泡之间有 0.5~2 秒间隔 |
| 已读不回 | 偶尔（10%）会晚点回 |
| 作息 | 睡眠时段收到消息有概率「没看见」，但关键词能叫醒 |
| 情绪 | 人设里的傲娇/撒娇/嘴硬会自然出现在消息里 |

### 主动消息

五种来源，每天大约 11 次：

```
作息（起床 / 早饭 / 午饭 / 晚饭 / 睡觉）   5 次
随机闲聊（一天 3 个随机时刻）              3 次
空窗升级（你半天没说话 → 她憋不住）          ≤2 次
失眠（偶尔半夜睡不着）                      0~1 次
```

**所有主动消息都有防打扰设计**：静默时段、每日上限、最小间隔、她刚说过话就不再发。

### B 站视频（双向）

**她主动分享：**

```
随机时刻 → 她按当前话题 + 自己的口味想一个搜索词
        → 搜 B 站（游客 cookie，不需要登录）
        → 过滤（10 秒~10 分钟 / 播放量 / 标题黑名单）
        → 她从候选里挑一个
        → 下载 720P 到本地
        → 抽帧（按视频长度自适应间隔）+ 语音转写（千问 ASR）
        → 云端视觉模型总结成一段 500 字内的内容描述
        → 她判断「这东西拿不拿得出手」—— 不合格就换一个重来
        → 通过 → 用她的语气说一句 + 带链接发给你
```

**你发链接给她：**

```
你发一个 b23.tv / bilibili.com 链接
  → 它先回一句「点开了」    （不让你干等）
  → 后台下载 + 看 + 总结
  → 她评论
```

**视频抽帧规则**（按长度自适应，帧间隔越往后越稀）：

| 视频时长 | 帧间隔 | 九宫格数 |
|---|---|---|
| 0~2 分钟 | 5 秒 | 12~24 张 |
| 2~4 分钟 | 7.5 秒 | 32 张 |
| 4~6 分钟 | 10 秒 | 36 张 |
| 6~8 分钟 | 12.5 秒 | 39 张 |
| 8~10 分钟 | 15 秒 | 40 张 |

**每张九宫格是 3×3、3840×3840，每格左上角带时间戳。** 视觉模型的图片 token 是封顶的（约 990/张，和尺寸无关），所以格子放大不额外花钱。

### 语音消息

你发语音，它会：

```
微信本地库 → SILK 文件 → 解码成 PCM → 千问 ASR → 文字
                                      ↓
                            附带声学特征（"偏低偏慢"）
                                      ↓
                        由模型结合内容判断情绪（不直接下结论）
```

### 配图

她可以主动发一张自己的照片。生成用的是通义万相，带角色参考图。

**默认开启需要你先开口要**（`image.requireAsk: true`）—— 出图是花钱的，不让她自说自话乱发。

### 微信里清上下文

在私聊里发：

```
清除本会话上下文
```

她会删掉这个会话的全部历史（只有这八个字完整匹配才触发）。

## 快速开始

### 1. 环境

- **Windows 10/11**（wechatauto 依赖 UIA，仅 Windows）
- **微信 4.x 桌面版**，已登录
- **Python 3.9+**
- **ffmpeg**（抽帧/音频提取，加到 PATH 或设 `FFMPEG_BIN`）

### 2. 安装

```bash
git clone https://github.com/<you>/furina-wechat-bot.git
cd furina-wechat-bot
pip install -r requirements.txt
```

### 3. 配置

```bash
cp bot-config.example.json bot-config.json
```

改 `bot-config.json`：

```jsonc
{
  // 凭据：默认去 DSH 的凭据库拿自己的 yaml；也可以直接填 apiKey
  "credentialsFile": "~/.dsh/.credentials.yaml",
  "credentialsRef": "DEEPSEEK_API_KEY",

  // 会话名必须和微信里显示的完全一致（备注优先于昵称！）
  "chats": [
    { "name": "旅行者", "mode": "always", "personaFile": "persona/furina.md",
      "proactive": true, "kind": "private" },
    { "name": "你的某个群", "mode": "wake", "kind": "group" }
  ],

  "video": { "enabled": true, "dailyLimit": 3 }
}
```

**凭据**的两种给法（任选）：

```yaml
# ~/.dsh/.credentials.yaml
DEEPSEEK_API_KEY: sk-xxxxxxxx
QWEN_API_KEY: sk-xxxxxxxx      # 语音转写/总结/出图要用
```

或者直接在 `bot-config.json` 里填 `"apiKey": "sk-..."`。

### 4. 跑起来

```bash
python wechat-bot.py
```

看板：<http://127.0.0.1:8765/console>

## 配置说明

配置文件很大（`bot-config.example.json` 里每条都有默认值），常用的几个：

### 会话（`chats`）

| 字段 | 说明 |
|---|---|
| `name` | 微信里显示的名字。**注意 `wechatauto` 取的是「备注优先，没备注才用昵称」**，改备注会导致找不到会话 |
| `aliases` | 备选名字，防止改备注后失联 |
| `mode` | `always`（每条都回）/ `wake`（被 @ 或抽中概率才回） |
| `personaFile` | 这个会话用哪个人设文件 |
| `proactive` | 是否允许主动消息 |

### 主动消息（`schedule` / `proactive`）

```jsonc
"randomChats": {
  "minPerDay": 3, "maxPerDay": 3,
  "minGapAfterHerMin": 20      // 她刚说过话，20 分钟内不触发闲聊
},
"proactive": {
  "dailyLimit": 2,             // 空窗升级每天最多 2 次
  "quietHours": [1, 7]         // 1~7 点不发
}
```

### 视频（`video`）

```jsonc
"video": {
  "enabled": true,
  "dailyLimit": 3              // 她主动分享，一天最多 3 个
}
```

### 人设（`persona/furina.md`）

**这是整个项目最重要的文件。** 它不是「角色设定集」，是**行为规范** —— 定义她怎么说话、怎么反应、什么不做。

自带的版本约 9700 token，包含：

- 消息的物理形状（几条气泡、多少字）
- 自称切换（「我」vs「本神」的残留与自我修正）
- 体面裂缝梯度（0~4，压力越大越露破绽）
- 反应公式（傲 → 娇，最后一条必须是软的）
- 回复分寸（他发多长你回多长）
- 暗恋的具体表现
- 不能碰的红线

**换角色 = 重写这个文件。** 其余代码不用动。

## 设计原则

### 1. 上下文隔离（视频不污染聊天）

她看视频时产生的中间数据 —— 语音转写、每帧描述、原始摘要 —— **全部用完就丢**。

只有两样东西进聊天记录：

```
（你看完的视频《标题》：一段 400 字的摘要）   ← user 消息，相当于"她看完记住的内容"
用她的语气说的一句话 + 链接                    ← assistant 消息
```

**为什么这么做**：视频材料有几千字，塞进聊天记录会稀释对话；但完全不记她又会「转头就忘」。折中方案是**记下她看完后记住的那几个点**。

### 2. DeepSeek 是无状态的

服务端不保存任何对话。每一轮都要把完整的 `messages` 重新发过去。

所以这个项目必须自己管上下文：

```
data/contexts.json   每个会话一个消息列表，每条写入都立即落盘
data/memory.json     超长对话被压缩后的长期记忆（system prompt 里注入）
```

`compactAtChars` 到了预算就把最老的一段压成摘要、从窗口里删掉。

### 3. 判断用角色自己的标准，不用规则

视频要不要分享？不是「内容是否健康」，而是**「这东西拿不拿得出手」**：

```
你见过的戏、看过的场面太多了。有些东西你根本不会往他那儿转 ——
不是因为它「不健康」，是因为它太掉价。
这种东西你转过去，丢的是你自己的脸。
```

**为什么不用关键词黑名单**：硬限制会误杀，而且写不完。让模型用角色的判断力来筛，反而更准，也更像人。

### 4. 消息形状优先于内容

人设里最靠前的一节是「一条消息的物理形状」：

```
默认 3 行，最多 5 行，一条不超过 60 字，单词不超过 26 字
不写括号里的内心戏
不用 emoji
```

**因为 LLM 写长文的惯性极强。** 不管内容多好，一旦变成一大段，就不像微信了。

## 已知限制

- **仅 Windows** —— wechatauto 依赖 UIA 和微信 4.x
- **微信更新可能挂** —— UI 自动化本身脆弱，微信改界面就得跟着改
- **B 站不登录只能 720P** —— 1080P 需要登录态
- **视觉模型认不准原神角色** —— 已在提示词里给了角色对照表，认不准会退化成描述外貌
- **长视频很粗** —— 40 张九宫格 = 360 个画面，10 分钟的视频每 15 秒一个切片
- **不看超 10 分钟的视频** —— 又慢又贵，还看不细
